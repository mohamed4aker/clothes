# MAS System - نظام إدارة الأعمال الكامل

نظام إدارة شامل للأعمال التجارية — **ASP.NET Core 8 + Blazor Server + SQL Server**.

> ⚠️ **مهم قبل ما تكمّل:** ده مش موقع HTML ساكن. ده تطبيق سيرفر (Blazor Server)
> محتاج **.NET runtime + SQL Server** شغالين على سيرفر حقيقي.
> **مينفعش يتنشر على GitHub Pages** ولا على أي استضافة ملفات ساكنة —
> اقرا قسم [النشر](#النشر) تحت.

---

## المميزات

### إدارة العمليات
- نقطة بيع POS بصور المنتجات
- بيع، شراء، مرتجعات بيع ومشتريات
- إدارة المخزون (تنبيهات، جرد، تسوية)
- تسليم درج الكاشير (جلسات الكاشير)

### التصنيع
- وصفات (BOM) بحساب التكلفة
- حاسبة الإنتاج العكسية
- أوامر إنتاج مع خصم خامات وإضافة منتج تام

### التقارير والداشبورد
- داشبورد (يومي/أسبوعي/شهري/سنوي)
- صافي الربح + COGS + متوسط الربح للفاتورة
- تقارير مبيعات ومشتريات ومخزون

### المتجر الإلكتروني
- متجر على `/shop` (أو `/shop/{slug}` لو عندك أكتر من براند)
- الدفع عند الاستلام (COD)
- تقسيم تكلفة الشحن (بائع/عميل)
- إدارة الطلبات بحالات (جديد/مؤكد/جاري/في الطريق/تم التسليم)
- تحويل الطلب لفاتورة تلقائياً عند التسليم

### العروض والكوبونات
- عروض بنسبة أو مبلغ ثابت، وكوبونات بحد استخدام

### أدوات إضافية
- توليد وطباعة الباركود، وطباعة فواتير حرارية
- Multi-tenant (Owner → Brands → Branches)
- صلاحيات حسب الدور

## نوع النشاط

النظام **مش مربوط بنشاط واحد**. فيه `BusinessType` بيدعم:
`Clothing` (ملابس) · `Pharmacy` · `VeterinaryPharma` · `Manufacturing` · `Restaurant` · `Generic`.

لو النشاط ملابس، اللي بيخدمك بالذات:
- **Variants** بخصائص (لون / مقاس) — جداول `ProductAttributes` و `ProductVariants`
- الباركود لكل variant
- المتجر الإلكتروني بصور المنتجات

البراند اللي بيتعمل تلقائياً أول تشغيل بيكون `Generic`.
غيّره لـ `Clothing` من صفحة **البراندات** لو نشاطك ملابس.

## التشغيل محلياً

### المتطلبات
- .NET 8 SDK
- SQL Server (Express أو LocalDB)
- Visual Studio 2022 (اختياري)

### الخطوات
```bash
dotnet restore
dotnet build
dotnet run --project src/MAS.Web
```
أو افتح `MAS.sln` في Visual Studio واضغط F5.

الداتابيز بتتعمل تلقائياً أول تشغيل (`EnsureCreated` + `DbSeeder`).

الـ Connection String الافتراضي بيشاور على **LocalDB**.
لو بتستخدم SQL Express غيّره في `src/MAS.Web/appsettings.json`.

### بيانات الدخول الأولى
```
Username: admin
Password: admin
```
(الإيميل `admin@maspos.com` بيشتغل برضه في خانة الدخول.)

> 🔴 **غيّر الباسورد ده فوراً** من صفحة الموظفين قبل أي نشر على النت.

## البيانات

المشروع **مفيهوش أي بيانات تجريبية** — لا منتجات، لا عملاء، لا فواتير، لا موردين.
ملفات الـ SQL في مجلد `database/` كلها `CREATE TABLE` من غير أي `INSERT`.

اللي بيتعمل تلقائياً أول تشغيل هو الحد الأدنى اللي النظام مش بيشتغل من غيره:

| اللي بيتعمل | العدد |
|---|---|
| Owner (المالك) | 1 |
| Brand ("شركتي") | 1 |
| Branch ("الفرع الرئيسي") | 1 |
| User (admin) | 1 |
| وحدات قياس (قطعة/كيلو/جرام/لتر/متر/علبة) | 6 |
| إعدادات البراند | 1 |

عايز تبدأ من الصفر تاني؟ صفحة **الإعدادات → تصفير البيانات** (`/reset-data`، للمالك بس)،
أو امسح الداتابيز وشغّل المشروع من جديد.

## النشر

### ❌ اللي مينفعش
| المكان | ليه لأ |
|---|---|
| **GitHub Pages** | بيقدّم ملفات ساكنة بس (HTML/CSS/JS). مفيش .NET runtime ولا SQL Server. |
| **Google Sites / Drive** | نفس السبب. |
| **Firebase Hosting** | استضافة ساكنة — مش بتشغّل Blazor Server. |

Blazor **Server** بيحتاج اتصال SignalR مفتوح مع سيرفر .NET شغال، وبيحتاج SQL Server.

### ✅ اللي ينفع
| الخيار | ملاحظات |
|---|---|
| **VPS** (Hetzner / Contabo / DigitalOcean) | الأرخص والأمرن. الخطوات كاملة في `DEPLOYMENT_GUIDE.md` |
| **Azure App Service + Azure SQL** | أسهل نشر لمشاريع .NET، بس أغلى |
| **Google Cloud Run + Cloud SQL** | لو مصرّ على جوجل: Docker image + Cloud SQL for SQL Server. لازم تفعّل **session affinity** عشان SignalR |
| **Windows Server + IIS** | لو عندك سيرفر ويندوز، شوف `INSTALL_ON_SERVER.txt` |

### GitHub دوره إيه هنا؟
GitHub مكان **الكود**، مش مكان تشغيل الموقع. الترتيب الطبيعي:
1. ترفع الكود على GitHub (نسخة احتياطية + تاريخ تغييرات)
2. تستأجر سيرفر/استضافة .NET
3. تعمل `dotnet publish` وترفع الناتج على السيرفر — أو تربط GitHub Actions بالسيرفر عشان ينشر تلقائي

### قبل أول نشر على النت
- [ ] اعمل `src/MAS.Web/appsettings.Production.json` من `appsettings.Production.json.example` وحط فيه الـ Connection String الحقيقي
      (الملف ده متجاهَل في `.gitignore` — **متحطّش فيه باسوردات وترفعه على GitHub**)
- [ ] لو هتشغّل `MAS.API`، اضبط `Jwt:Key` (32 حرف على الأقل) من متغير بيئة `Jwt__Key`. المشروع بيرفض يشتغل في الإنتاج من غيره
- [ ] غيّر باسورد `admin`
- [ ] فعّل HTTPS
- [ ] اعمل خطة Backup للداتابيز

## حدود GitHub للرفع

| الحد | القيمة | ملاحظات |
|---|---|---|
| حجم الملف الواحد | **50 MB** تحذير · **100 MB** رفض | فوق كده لازم Git LFS |
| حجم الريبو | **يُنصح أقل من 1 GB** · **5 GB** حد إداري | |
| الرفع من الويب (Upload files) | **25 MB** للملف · **100 ملف** في المرة | استخدم `git push` بدلها |
| Git LFS (الخطة المجانية) | **1 GB** تخزين · **1 GB** bandwidth شهرياً | |
| الـ push الواحد | **2 GB** | |
| GitHub Pages | **1 GB** للموقع · **100 GB** bandwidth شهرياً | ملفات ساكنة بس |

المشروع ده **~1 MB** كود بس، فمفيش أي مشكلة —
بشرط إن `bin/` و `obj/` ميترفعوش (متظبطين في `.gitignore`).
